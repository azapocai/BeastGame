## 2026-08-12 方案变更：第二种方案

Video 9 证明，本计划完成的“有序解析接触 + 全局解析路线”虽然通过了纯逻辑和编译门，但会把玩家画出的松链大圈重新最短化，也无法持续识别位于大圈内部、尚未被边界穿过的多个目标。因此它只保留为解析紧链基线，不能继续通过增加公切线分支、接触冷却或吸附条件扩展成最终多人模型。

下一阶段改为三层权威架构：

1. 规则级持久引导链保存松弛、大圈、路径历史和包围候选。
2. 解析接触层绑定引导链局部区间，只计算精确切点、直线、圆弧、弧长和张力，不再决定全局最短路线。
3. 纯视觉动力层只补充摆动、回弹和链节表现，不参与玩法。

本文件后续章节用于说明已经完成、可复用或必须废止的旧切片。新的模块边界、固定预算、Slice 0–6、验收门和停止条件统一记录在 `docs/CHAIN_OPTIMIZATION_DESIGN.md`，不在两份文档中维护两套现行计划。

## 1. 总体决策

本阶段采用“锁链子系统定向重构”，不重写整个 Demo，也不直接把 `MAX_CONTACTS` 从 1 改大。

保留内容：

- `ChainContactSolver` 的单圆连续接触、切点、圆弧和绕行角算法。
- 玩家、敌人、铁球、输入、房间和现有普通碰撞逻辑。
- 现有单接触玩法阈值，除非后续切片明确调整。
- `Graphics` 调试路径，作为几何对照和问题诊断工具。

需要重构的内容：

- 接触点从“只有第一个有效”升级为从玩家端到铁球端的有序拓扑。
- 路径构造、长度、张力、碰撞检测和绘制统一读取同一份权威路径快照。
- 长度约束从“处理 `contacts[0]`”升级为处理完整路径及其接触对象。
- 释放过渡从单目标 handoff 升级为任意旧路径到新路径的连续过渡。
- 正式表现由每帧 `Graphics` 全量重画逐步迁移到静态 Sprite、角色 Sprite 和链节 Sprite 池。

## 2. 范围与非目标

### 2.1 本计划范围

- 一条锁链同时与 0–4 个普通圆形敌人形成稳定、有顺序的身体接触。
- 多接触路径参与绘制、长度、张力、移动限制、拉脱和眩晕判断。
- 中间接触消失、目标眩晕、目标关闭碰撞以及释放路径命中新目标时，路径连续过渡。
- 使用固定预算、复用缓冲区和候选筛选控制小游戏 CPU、GC 和渲染成本。
- 增加图片链节渲染器，保留 `Graphics` 调试渲染器。

### 2.2 本计划非目标

- 不增加 AI 队友、完整 Roguelike 循环、新关卡或新敌人类型。
- 不引入 Box2D 绳索关节或大量刚体链节。
- 不实现可自相交、打结、链条之间互相碰撞的物理绳索。
- 不同时支持多条独立锁链；本阶段性能预算按场上 1 条活动锁链计算。
- 不在逻辑重构阶段顺手更换角色美术、特效或 UI 风格。
- 不因图片迁移删除 `Graphics` 调试能力。
- 本计划不包含微信真机发布；真机性能门作为后续独立验证任务保留。

## 3. 架构目标

最终每个逻辑帧只发布一份权威路径：

```text
玩家/铁球/敌人位置
        │
        ▼
有序接触拓扑 ChainContactTopology
        │
        ▼
多接触路径求解 MultiContactRouteSolver
        │
        ▼
ChainRouteSnapshot
  ├─ 路径点和累计长度
  ├─ 接触顺序与各自路径区间
  ├─ 总长度和张力
  └─ 版本号/调试统计
        │
        ├─ 碰撞与新接触检测
        ├─ 长度和控制权约束
        ├─ 拉脱/眩晕规则
        ├─ Graphics 调试渲染
        └─ Sprite 链节正式渲染
```

建议新增或调整的职责模块：

| 模块 | 职责 | 是否含 Cocos 依赖 |
|---|---|---:|
| `ChainContactSolver` | 单个圆形身体的连续接触几何 | 否，保留 |
| `ChainContactTopology` | 保存接触对象、顺序、方向、生命周期和稳定 ID | 否 |
| `MultiContactRouteSolver` | 根据端点和有序接触构造完整路径 | 否 |
| `ChainRouteSnapshot` | 对外发布只读路径、长度和接触区间 | 否 |
| `ChainConstraintSolver` | 使用完整路径执行链长和控制权约束 | 否 |
| `ChainReleaseTransition` | 旧路径到新路径的连续插值与活动碰撞路径 | 否，改造 |
| `ChainSnareSystem` | 编排接触、规则、眩晕、拉脱和快照 | 否 |
| `GraphicsChainRenderer` | 几何调试和无美术资源回退 | 是 |
| `SpriteChainRenderer` | 使用图片池显示正式链节 | 是 |

## 4. 固定技术与性能预算

以下预算在计划阶段固定，后续只有独立评审才能扩大：

| 项目 | 默认预算 | 硬上限/降级规则 |
|---|---:|---|
| 活动锁链 | 1 条 | 不在本阶段扩展 |
| 正式房间活动敌人 | 12 个 | 房间生成和激活逻辑不得超过 |
| 同时稳定接触 | 4 个 | 第 5 个只作为候选，不进入拓扑 |
| 精确检测候选敌人 | 8 个/帧 | 宽相位后按路径距离保留最近 8 个 |
| 权威路径点 | 48 个目标值 | 最多 64 个，超过时降低圆弧采样密度 |
| 正式链节 Sprite | 48 个常用值 | 预分配最多 64 个，不运行时创建 |
| 释放过渡采样 | 26 个基线 | 不随敌人数线性增加 |
| 链条渲染批次 | 1 个目标值 | 因前后穿插最多允许 3 个批次 |
| 运行时节点分配 | 0/帧 | 场景加载后不得创建/销毁链节节点 |
| 链条逻辑临时数组 | 0 个稳定态分配/帧 | 使用复用数组或固定容量缓冲区 |

没有真机数据前，临时性能验收目标为：

- 4 个接触、12 个活动敌人、8 个精确候选时，链条逻辑桌面预览 p95 不高于 1 ms；该值只用于防止明显退化，不替代真机数据。
- 连续运行 5 分钟后，链条相关数组容量、节点数量和材质实例数量保持稳定。
- 正式模式关闭场景级每帧全量 `Graphics` 重画；调试模式允许启用。
- 单接触情况下，重构前后路径、角度、张力和拉脱结果在允许误差内一致。

## 6. 详细任务切片

### Slice 0.1：冻结当前单接触基线

目标：建立重构前的可执行行为基线，防止“支持多接触”时破坏已经验证的单接触效果。

改动范围：

- 扩充 `tests/chain-snare.test.js` 的单接触固定数据。
- 记录直接接触、顺时针绕行、逆时针绕行、反向退绕、45° 拉脱、135° 稳定缠绕、C 强制拉脱和释放路径接管。
- 对关键路径点、总路径长度、总接触角、玩家绕行角和眩晕状态使用明确误差范围。

产物：

- 一组重构前必须全部通过的回归测试。
- 测试夹具名称能够表达场景，不依赖 HUD 字符串判断。

验收条件：

- 现有测试全部通过。
- 新基线测试重复运行结果一致。
- 不改变运行时代码和现有玩法结果。

非目标：不添加多接触代码，不优化绘制。

### Slice 0.2：增加低开销性能与路径统计

目标：在重构前获得可比较的路径构造次数、路径点数量和候选检测数量。

改动范围：

- 新增只在调试构建或 F2 模式读取的 `ChainRuntimeStats`。
- 至少统计：每帧路径构造次数、发布路径点数、精确线段圆检测次数、约束迭代次数、活动接触数、链节显示数。
- 统计对象固定复用，不向每帧日志输出，不拼接大量字符串。

验收条件：

- 默认模式没有控制台刷屏。
- 统计关闭时不创建额外数组。
- 能测出当前 `update`、约束和绘制阶段重复构造路径的次数。

非目标：本切片只测量，不提前修改求解流程。

### Slice 1.1：定义 `ChainRouteSnapshot` 权威路径契约

目标：让渲染、碰撞、张力和规则不再各自重建路径。

建议字段：

```ts
interface ChainRouteSnapshot {
  readonly revision: number;
  readonly pointCount: number;
  readonly points: ReadonlyArray<Point2D>;
  readonly cumulativeLengths: ReadonlyArray<number>;
  readonly totalLength: number;
  readonly tension: number;
  readonly contacts: ReadonlyArray<RouteContactRange>;
}
```

改动范围：

- 新建纯数据契约和接触路径区间定义。
- 当前单接触路径先适配为该快照，不改变求解算法。
- 明确快照在一个逻辑帧内不可被消费者修改。

验收条件：

- 渲染和 HUD 可以读取快照。
- 快照路径与当前 `getVisualSnapshot()` 输出在误差内一致。
- Cocos 类型不进入纯逻辑模块。

### Slice 1.2：每帧只发布一次最终路径

目标：消除 `update()`、`enforceRoutedLength()` 和绘制阶段对正式路径的重复构造。

改动范围：

- `ChainSnareSystem` 在逻辑更新末尾发布一个带 revision 的最终快照。
- 约束内部允许使用复用 scratch buffer 多次试算，但只发布最后结果。
- `ChainArenaController.draw()` 只读取已发布快照，不再调用会重新求解的接口。
- `getVisualSnapshot()` 改成只读适配器或被明确的快照接口替代。

验收条件：

- 正式路径每帧只发布一次。
- 绘制不改变锁链状态或路径 revision。
- Slice 0.1 单接触基线全部通过。
- 统计能区分“内部试算次数”和“最终发布次数”。

### Slice 1.3：解耦锁链渲染接口

目标：让 `Graphics` 和未来 Sprite 渲染器消费同一快照，可独立切换。

改动范围：

- 定义 `ChainRenderer` 接口，只接收快照和显示状态。
- 将当前 `TetherRenderer.drawChain()` 包装为 `GraphicsChainRenderer`。
- 增加正式/调试渲染开关，但默认表现保持不变。

验收条件：

- 切换渲染器不会改变接触、长度、张力或眩晕结果。
- `GraphicsChainRenderer` 不调用任何玩法求解方法。

### Gate A：单接触等价门

进入多接触实施前必须满足：

- Slice 0.1 全部回归测试通过。
- 单接触路径没有可见跳变。
- C、自动拉脱和释放接管仍可持续测试。
- 每帧只存在一份对外权威路径。
- 若不满足，停止阶段 2，先修复等价性，不允许带缺陷进入多接触。

### Slice 2.1：建立有序接触拓扑

目标：把 contact 从普通数组变成具有稳定顺序和生命周期的路径拓扑。

每个拓扑项至少包含：

- 稳定 contact ID。
- 目标敌人引用或稳定实体 ID。
- 单圆 `ContinuousCircleContact`。
- 从玩家端到铁球端的顺序索引。
- 接触建立、稳定、释放、失效状态。
- 最近有效路径区间，用于顺序稳定和过渡。

顺序规则：

- 新接触按命中时在当前权威路径上的累计长度比例插入。
- 轻微位置变化不得交换相邻接触顺序。
- 只有明确解除、路径重建或拓扑失效才能改变顺序。
- 同帧多个候选按路径命中距离排序，而不是按敌人数组顺序决定。

验收条件：

- 只含一个接触时输出与旧系统一致。
- 两个候选同时命中时顺序确定且可重复。
- 敌人数组顺序变化不会改变拓扑结果。

### Slice 2.2：实现多接触路径构造器

目标：构造玩家→接触 A→接触 B→接触 C→铁球的连续路径。

关键要求：

- 单个接触继续复用 `ChainContactSolver` 的连续展开角。
- 每个身体的切入、圆弧和切出由相邻自由链段决定，不能继续把所有 contact 都直接使用全局玩家和铁球作为端点。
- 相邻圆形身体之间使用稳定的公切线或等价的连续几何解。
- 路径点按长度和曲率自适应采样，总点数受 64 点硬上限约束。
- 生成接触对应的起止点索引和累计长度区间。

实施建议：

- 先支持 2 个不重叠圆形目标，再扩展到 3 个。
- 使用固定 2–3 次的邻接几何迭代，不允许无上限收敛循环。
- 两个接触圆重叠、无有效公切线或数值异常时，拒绝较新的接触并保持上一帧有效路径。

验收条件：

- 2 个和 3 个目标都能形成连续路径。
- 路径不穿过任何已经登记的接触圆内部。
- 路径点无 `NaN`、无无穷值、无突然跨越画面的跳点。
- 接触顺序稳定，反向移动会沿原拓扑退绕。

### Slice 2.3：多目标候选发现与加入

目标：允许链条当前路径命中新敌人并加入有序拓扑。

改动范围：

- 先计算路径整体或分段 AABB，排除明显不相交的敌人。
- 对剩余候选进行精确线段圆检测。
- 收集同帧命中结果，按路径累计距离排序。
- 逐个试加入，每加入一个都进行链长预算和路径有效性验证。
- 达到 4 个接触后停止加入；第 5 个不得悄悄替换已有接触。

验收条件：

- 12 个活动敌人中只有接近链条的目标进入精确检测，精确候选最多保留 8 个。
- 同帧命中两个敌人时按玩家端到铁球端的真实路径顺序加入。
- 超长、重叠或无解候选被拒绝时，现有路径保持不变。

### Slice 2.4：接触移除与任意路径过渡

目标：移除头部、中间或尾部 contact 时不重新生成一条瞬移链条。

改动范围：

- 将 `ChainReleaseTransition` 改成通用的旧快照→新快照过渡。
- 使用路径累计长度重采样，旧路径节点连续收敛到新路径。
- 过渡中的活动路径继续参与新接触检测。
- 被释放旧目标保留短暂 pass-through 保护；其他合格目标可以接管。

验收条件：

- 分别移除第 1、第 2、第 3 个 contact，链条都从旧形状连续恢复。
- 中间 contact 消失后两侧路径连续连接，不出现整条链瞬移。
- 过渡路径命中新目标时从命中区域接管，不重新绘制另一条链。

### Gate B：多接触拓扑正确门

进入规则与性能阶段前必须满足：

- 0、1、2、3、4 接触均有确定路径。
- 顺序不依赖敌人数组顺序。
- 新增、移除、眩晕关闭碰撞和释放接管均无路径跳变。
- 任何无解输入都能回退到上一帧有效状态，不产生 `NaN`。
- 路径、碰撞、长度和绘制使用同一个快照 revision。

### Slice 3.1：把缠绕指标改成逐接触数据

目标：每个 contact 独立维护总接触角、新增弧、玩家绕行角和拉脱资格。

改动范围：

- 将当前只读取 `contacts[0]` 的 getter 改为按 contact ID 查询。
- 增加用于 HUD/调试的接触摘要数组。
- `state` 不再代表唯一目标；增加整条链状态与逐目标状态的区分。

验收条件：

- 两个敌人的角度互不覆盖。
- 一个敌人反向退绕不会清空另一个敌人的累计值。
- HUD 至少能选中并显示一个接触，同时 F2 能显示全部接触摘要。

### Slice 3.2：完整路径长度与张力约束

目标：张力和移动限制基于整条多接触路径，而不是端点直线或第一个 contact。

改动范围：

- 总长度读取 `ChainRouteSnapshot.totalLength`。
- 使用相邻路径切线决定玩家端和铁球端的修正方向。
- scratch 路径缓冲区复用；约束迭代次数固定上限。
- 约束失败时保持上一个合法姿态，禁止无限二分或无限迭代。

验收条件：

- 任意接触顺序下路径长度不超过最大链长容差。
- 张力达到上限时玩家不会因中间接触突然改变到错误方向。
- 无 contact 时保持原铁球直线约束行为。

### Slice 3.3：多接触控制权与特殊标记单位

目标：保持玩家对普通敌人、锁链和铁球的绝对控制，只允许显式标记单位反向影响端点。

规则：

- 普通敌人导致路径超长时，优先回退该敌人的本帧移动。
- 多个普通敌人同时超长时，按实际造成的路径增量处理，不按数组顺序处理。
- `tetherInfluence` 单位才可把修正传到玩家与铁球，并触发玩家摔倒。
- 未带标记的中间 contact 不得作为力量传递源把玩家拖走。

验收条件：

- 3 个普通敌人移动时不夺走玩家控制。
- 只有带标记目标主动造成超长时才影响玩家和铁球。
- 标记单位与普通单位同时接触时，控制权结果可重复且有测试覆盖。

### Slice 3.4：多接触拉脱和 C 键语义决策

目标：在编码前明确多接触下自动拉脱和手动拉脱影响哪些目标。

推荐默认规则：

- 自动拉脱：只处理本帧达到“总接触角 + 玩家绕行角 + 满张力继续拉动”条件的 contact。
- 同帧多个 contact 合格：按玩家端到铁球端的路径顺序逐个处理，但每帧最多触发一个，避免路径连续多次重建。
- C 强制测试：默认只拉脱玩家端第一个当前 contact，保持现有“当前接触”语义；F2 显示将被 C 处理的目标。
- 若需要“一键拉脱并眩晕全部当前接触”，应作为明确的新测试模式单独授权，不能在本切片中默认加入。

验收条件：

- 用户确认 C 键规则后才实施。
- 拉脱一个目标不会清除其他目标的绕行数据。
- 拉脱后的旧路径连续过渡，其他 contact 保持或按几何重新求解。
- 同帧不发生多次互相覆盖的 release transition。

### Slice 4.1：消除稳定态路径内存分配

目标：降低微信小游戏 JavaScript GC 抖动风险。

改动范围：

- 路径点、累计长度、候选命中和 scratch 路径使用复用缓冲区。
- 避免在高频路径中使用 `map()`、`filter()` 和对象展开生成新数组。
- 颜色、渲染状态和调试统计使用缓存对象。
- 缓冲区只在超过历史容量时增长，达到硬上限后不继续扩容。

验收条件：

- 热身后稳定 5 分钟，链条相关数组容量不持续增长。
- 节点数量、材质数量和链节池大小保持不变。
- 单接触与多接触测试全部通过。

### Slice 4.2：碰撞候选宽相位

目标：让敌人数量增加时，精确检测成本不按全部敌人×全部链段无条件增长。

实施顺序：

1. 先实现整条路径扩展 AABB。
2. 当前正式房间活动敌人硬上限为 12，先不引入复杂空间树；只有未来独立评审批准扩大敌人预算时，才增加简单均匀网格。
3. 只有 AABB 命中的敌人进入分段精确检测。

验收条件：

- 敌人远离链条时不执行精确线段圆求交。
- 候选筛选不得漏掉高速移动敌人；AABB 需要按敌人半径和本帧位移扩展。
- 统计能显示宽相位候选数和精确检测次数。

### Slice 4.3：固定预算与可控降级

目标：极端路径仍保持固定上限，不以帧率换取无限视觉精度。

降级顺序：

1. 降低松弛直线段的视觉链节密度。
2. 降低低曲率圆弧的额外采样。
3. 保留接触切点、圆弧端点和碰撞关键点。
4. 不降低接触判断、张力和链长计算的正确性。

验收条件：

- 路径不会超过 64 点。
- Sprite 不会超过 64 个活动链节。
- 降级时接触位置和拉脱结果不变，只降低非关键视觉密度。

### Gate C：逻辑性能门

进入正式图片渲染前必须满足：

- 4 接触、12 活动敌人、8 精确候选压力夹具稳定运行。
- 权威路径每帧只发布一次。
- 热身后没有持续的链条数组或节点分配。
- 路径点、候选数和约束迭代均不超过固定上限。
- 单接触回归、多接触拓扑、控制权和释放过渡测试全部通过。

### Slice 5.1：拆分静态 Graphics 与动态 Graphics

目标：先移除当前每帧重复绘制背景网格和边界的成本。

改动范围：

- 背景、网格和固定边界改成静态 Sprite、预渲染纹理或只生成一次的节点。
- 动态调试 Graphics 与正式表现节点分开。
- F2 关闭时不提交调试路径和最大长度圆。

验收条件：

- 正式模式不再每帧清空并重画静态背景。
- 画面尺寸和逻辑坐标不变。
- 调试开关仍能显示碰撞与路径信息。

### Slice 5.2：实现固定容量链节 Sprite 池

目标：用图片链节替代当前每个链节点 `circle()+fill()` 的正式表现。

实现要求：

- 场景加载时一次性创建最多 64 个链节 Sprite，运行时只启用、停用和更新变换。
- 按权威路径累计长度等距采样，不按每个折线段独立重新计数，避免接缝密度突变。
- 链节根据局部切线旋转；张力只改变允许合批的颜色或贴图状态。
- 所有链节使用同一图集、材质、混合模式和渲染层。
- 不为每个链节添加脚本组件，不在 `update()` 中 instantiate/destroy。

验收条件：

- 直线、单圆弧、双接触和释放过渡都使用同一批链节连续移动。
- 路径改变时不存在“重新生成另一条链”的闪现。
- 正式链节数不超过 64。
- 不考虑前后穿插时，链条目标为 1 个批次。

### Slice 5.3：处理链条与敌人的前后穿插

目标：让绕体链条在视觉上能够部分位于敌人前方、部分位于后方。

改动范围：

- 使用 `RouteContactRange` 将链节分成后层、主体层、前层。
- 优先使用固定 2–3 个池和渲染层，不为每个 contact 创建新材质。
- 层级切换必须沿用相同链节采样位置，不能改变逻辑路径。

验收条件：

- 最多 4 个接触时渲染批次仍不超过 3 个目标上限。
- 前后层切换没有明显断链。
- 调整渲染层不会影响碰撞或张力。

### Slice 5.4：保留 Graphics 回退和动态网格升级点

目标：保留调试基准，并避免现在就过早实现复杂动态网格。

规则：

- `GraphicsChainRenderer` 继续作为 F2 调试和无图片资源时的回退。
- 正式模式默认使用 `SpriteChainRenderer`。
- 只有出现以下任一情况，才单独立项实现动态网格：活动链节长期需要超过 48、链条批次超过 3、Sprite 节点更新成为真机 CPU 热点，或美术要求连续纹理而链节池无法满足。

验收条件：

- 两种渲染器能读取同一快照并快速切换。
- 切换时玩法状态完全一致。

## 8. 风险清单与停止条件

| 风险 | 预防措施 | 停止条件 |
|---|---|---|
| 多圆之间不存在稳定公切路径 | 候选试加入、数值验证、保留上一帧合法路径 | 出现 `NaN` 或整条链跨屏跳变 |
| contact 顺序频繁交换 | 稳定 ID、路径区间、只在明确失效时重排 | 顺序受敌人数组顺序影响 |
| 多次过渡覆盖 | 每帧最多触发一个释放拓扑事件 | 同帧出现两个 transition 所有者 |
| 约束计算倍增 | 固定迭代、scratch 缓冲、一次最终发布 | 迭代次数无上限或稳定态持续分配 |
| Sprite 节点过多 | 64 个固定池、按弧长降采样 | 运行时创建链节节点 |
| 合批失效 | 同图集、材质、混合与固定层级池 | 单条链常态超过 3 个批次 |
| 逻辑与画面分叉 | 所有 Renderer 只读同一快照 | Graphics 与 Sprite 路径不一致 |

出现任一停止条件时，不继续下一个切片；应先定位当前切片的模型或边界问题，不通过继续叠加条件规避。

## 9. 完成定义

以下条目是 2026-08-11 解析基线的历史完成定义，不再代表多人松链方案已完成：

- 一条锁链能够稳定维护最多 4 个有序身体接触。
- 多接触路径是绘制、碰撞、长度、张力和移动约束的唯一来源。
- 单接触现有玩法和释放表现没有回归。
- 任意 contact 加入、移除或眩晕时，链条从旧路径连续过渡到新路径。
- 普通敌人不能借锁链夺走玩家控制；只有显式标记单位可以产生反向影响。
- 路径点、接触数、检测候选、约束迭代和链节节点均有固定上限。
- 正式链条使用图片链节池，`Graphics` 只承担调试或回退。
- 编辑器压力夹具和完整测试矩阵通过。
- 文档同步更新 `PROJECT_DESIGN.md` 与 `DEMO_STATUS.md`；真机性能结果在未来独立任务中记录。

现行完成定义还必须满足：规则级持久引导链能够保存玩家画出的松链大圈；圈内多个目标可持续进入规则候选；解析层只局部精修且不覆盖路径历史；每个目标可独立加入、退绕、释放和眩晕。完整标准见 `docs/CHAIN_OPTIMIZATION_DESIGN.md` 第 10 节。
