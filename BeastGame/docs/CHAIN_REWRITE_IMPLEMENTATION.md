# 锁链有限重写：实现与验收基线

> 状态：已接入 Demo 运行路径，等待 Cocos 编辑器手感复验  
> 更新：2026-08-12  
> 引擎：Cocos Creator 3.8.8

## 1. 为什么重写

Video 10 暴露的角色乱跳不是单个参数错误，而是运行时存在多个位置权威：玩家输入先写坐标，铁球直接距离约束再次修改玩家，旧锁链按另一条路径重复修正，最后玩家—敌人碰撞又覆盖坐标。与此同时，规则引导链、解析圆弧和释放路径都可能成为“当前链条”，造成画面、张力与移动约束互相矛盾。

因此停止继续修补旧 `ChainSnareSystem`，采用有限重写：只替换链条模拟和铁球房运动提交，不扩大到 Roguelike、AI、美术或微信真机适配。

## 2. 冻结的玩法要求

1. 玩家输入是普通情况下的最高优先级。
2. 链长达到上限时只裁剪越界分量，不允许反向、横跳或多次位置回写。
3. 普通敌人可改变链形、被链条绊倒，但不能借锁链移动玩家或铁球。
4. 只有显式 `tetherInfluence` 标记单位可以拖动玩家与铁球，并触发玩家摔倒。
5. 敌人眩晕时关闭实体碰撞，玩家、铁球和链条均可穿过。
6. 自动眩晕条件是同一条链上的局部绕角至少 45°且张力至少 98%。
7. C 是专项强制测试：无论是否达到自动门槛都启动同链收紧；存在接触时只强制眩晕玩家端第一个当前接触，无接触时只播放收紧。其他目标继续独立判定。
8. 拉直过程复用原 24 个链节点，不创建第二条释放链或替换路径。
9. 单条活动链最多处理 12 个敌人、4 个同时接触，固定 24 个规则节点。

Video 11 后铁球锁链最大长度由 592 调整为 396；张力按各链段不超过其物理段长的有效总长计算，局部碰撞投影残差不得把未拉满链条误报为满张力。

Video 11 同时确认自动眩晕后的链形没有进入恢复。现已让自动眩晕和 C 共用 0.24 秒同节点收紧过程，眩晕后原链自然回直，不生成第二条 release 路径。

## 3. 当前单权威架构

### `PlayerState.prepareMotion`

- 更新时间、闪避、倒地和速度状态。
- 只返回本帧期望位移，不提交世界坐标。
- 旧 `update` 仅作为无运动求解器房间的兼容入口。

### `ArenaMotionResolver`

- 是铁球房内玩家最终位置的唯一运行时提交者。
- 固定顺序：输入提案 → 场地边界 → 玩家/活动敌人实体阻挡 → 直接链长上限。
- 铁球撞玩家时移动铁球；铁球撞普通敌人时移动敌人，均不反向推走玩家。
- 最终只做一次径向链长投影，不执行迭代式玩家纠正。
- `applyTaggedTetherInfluence` 是唯一例外入口，并在内部再次检查显式单位标记。

### `ChainSimulation`

- 维护唯一一组 24 个跨帧 PBD 折线节点。
- 节点同时供碰撞、接触顺序、局部绕角、张力、眩晕判定和渲染读取。
- 绝不写玩家、铁球或敌人的位置。
- 长度和碰撞投影会同步节点的上一帧坐标，防止纠正量在下一帧被误当成速度。
- 精确重合时使用确定性接触侧，避免链条在敌人两侧逐帧翻转。
- C 通过收紧同一组节点完成过渡；快照对象和点对象均复用。

### `ChainRouteSnapshot`

- 是玩法与 Sprite/Graphics 渲染共同读取的唯一发布路径。
- 每逻辑帧发布一次；消费者只读。
- 点、累计长度与接触范围使用固定容量/复用缓冲区，稳定态不按帧创建链条对象。

### 旧模块状态

`ChainSnareSystem`、`ChainReleaseTransition`、解析接触和旧多接触求解器暂时保留为历史对照，避免未经审查删除用户已有工作；`ChainArenaController` 已不再导入或调用它们。后续只有在新路径通过编辑器验收后，才单独做逐文件退役清理。

## 4. 每帧执行顺序

1. 输入生成玩家期望位移。
2. 铁球只积分自身速度和边界。
3. 敌人更新 AI；敌人之间做固定两轮实体分离。
4. `ArenaMotionResolver` 一次提交玩家位置，并处理玩家/铁球/敌人的单向碰撞权威。
5. 若上一帧满张力接触来自 `tetherInfluence` 单位，运动求解器应用该单位的实测位移并触发摔倒。
6. `ChainSimulation` 用最终端点和敌人位置做固定子步，发布一份路径快照。
7. 自动眩晕或 C 事件改变敌人状态；渲染只读取上述快照。

普通敌人永远没有从第 6 步回写第 4 步玩家位置的通道。

## 5. 性能边界

| 项目 | 上限/策略 |
| --- | --- |
| 活动锁链 | 1 条 |
| 活动敌人 | 12 |
| 同时发布接触 | 4 |
| 链节点 | 固定 24 |
| 约束迭代 | 默认 4，硬上限 6 |
| 逻辑步长 | 60 Hz |
| 单渲染帧补步 | 最多 3 |
| 可见链节 Sprite | 最多 64，固定池 |
| 热路径分配 | 节点、contact、range、累计长度和快照对象复用 |

当前 Node 压力夹具覆盖 12 敌人运行 120 逻辑帧，并检查节点和接触上限。它只能证明算法预算受控，不能替代微信低端真机 CPU、GC、GPU 和 draw call 测量。

## 6. 已执行的严格自动测试

新测试文件：`tests/chain-rewrite.test.js`。

- `prepareMotion` 不写玩家坐标。
- 普通敌人的链条接触不改变已提交玩家位置。
- 链长裁剪不反转玩家输入方向。
- 玩家对铁球、铁球对普通敌人的单向碰撞权威。
- 眩晕敌人允许玩家穿过。
- 普通单位被特殊影响入口拒绝；只有 `tetherInfluence` 单位能平移端点并使玩家摔倒。
- 24 节点路径、真实接触累计长度、只读快照和节点对象复用。
- C 在有接触和无接触时都启动同链过渡。
- 多个接触按链节点顺序发布，且受固定上限约束。
- 静止对称接触连续 120 帧不换边。
- 局部绕角 ≥45°且张力 ≥98%时自动眩晕。
- 自动眩晕后原节点链进入收紧，弯曲偏差持续下降而不是冻结大圈。
- 单链段局部求解超长不能把整条链误报为满张力。
- 12 敌人预算压力夹具。
- 控制器结构测试确保旧链权威、旧二次长度约束和旧耦合碰撞不再接入运行路径。

同时保留并运行旧 `tests/chain-snare.test.js` 作为历史模块回归，但它不再代表当前运行架构的验收标准。

## 8. 下一步验收

在 Cocos 编辑器只验证当前单房间：

1. 连续移动和闪避后方向是否完全可控，不出现无输入侧移或瞬移。
2. 单敌人接触时链条是否始终保持同侧弯曲。
3. 绕角达到 45°并把链拉满时是否自动眩晕。
4. 未绕住、有接触、无接触三种状态按 C，是否都由原链连续收紧。
5. 多敌人接触、其中一个眩晕或离开后，其他链段是否保持连续。
6. 铁球压在眩晕敌人位置、敌人恢复碰撞时是否仍有生硬弹开；该项若失败，应单独设计恢复分离，不回到锁链架构继续打补丁。
