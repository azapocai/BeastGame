# 锁链有限重写：实现与验收基线

> 状态：已接入 Demo 运行路径，等待 Cocos 编辑器手感复验  
> 更新：2026-08-13
> 引擎：Cocos Creator 3.8.8

## 1. 为什么重写

Video 10 暴露的角色乱跳不是单个参数错误，而是运行时存在多个位置权威：玩家输入先写坐标，铁球直接距离约束再次修改玩家，旧锁链按另一条路径重复修正，最后玩家—敌人碰撞又覆盖坐标。与此同时，规则引导链、解析圆弧和释放路径都可能成为“当前链条”，造成画面、张力与移动约束互相矛盾。

因此停止继续修补旧 `ChainSnareSystem`，采用有限重写：只替换链条模拟和铁球房运动提交，不扩大到 Roguelike、AI、美术或微信真机适配。

## 2. 冻结的玩法要求

1. 玩家输入是普通情况下的最高优先级。
2. 链长达到上限时只裁剪越界分量，不允许反向、横跳或多次位置回写。
3. 普通敌人可改变链形、被链条绊倒，但不能借锁链移动玩家或铁球。
4. 只有显式 `tetherInfluence` 标记单位可以拖动玩家与铁球，并触发玩家摔倒。
5. 敌人眩晕时关闭实体碰撞，玩家、铁球和链条均可穿过。
6. 自动眩晕条件是同一条链上的局部绕角至少 45°、张力至少 98%，并且接触建立后存在玩家主动切向绕行证据。敌人主动撞上已经拉满的静止链条不会自动眩晕。
7. C 是专项强制测试：无论是否达到自动门槛都启动同链收紧；存在接触时只强制眩晕玩家端第一个当前接触，无接触时只播放收紧。其他目标继续独立判定。
8. 拉直过程复用原 24 个链节点，不创建第二条释放链或替换路径。
9. 单条活动链最多处理 12 个敌人、4 个同时接触，固定 24 个规则节点。

Video 11 后铁球锁链最大长度由 592 调整为 396；Video 14 再缩短五分之一到 317。张力不再使用会保留松弛轮廓的 PBD 折线总长：自由区间按两端最短直线计长，只有当前真实身体接触区间保留绕体路径长度。局部碰撞投影残差或玩家回走后的松弛弯曲都不得把未拉满链条误报为满张力。

Video 14 后续表现复验确认不能同时缩小链节和排列间距，否则同一链长会出现过量图片并形成实心管。排列间距保持 14 像素，单个链节图标为原 14×20 像素的一半，即 7×10 像素。黄色只表示与自动滑脱一致的 98% 满张力门槛；玩家向内回走使有效路径低于门槛后，颜色与自动滑脱资格必须在同一逻辑帧解除。

满张力且没有真实身体接触时，24 个规则节点必须从进入满张力时的当前弧线，在固定 0.28 秒过渡内连续拉至两端直线并清除残留节点速度；PBD 松弛轮廓不得持续显示为弧线。真实接触敌人的绕体区间不适用此收直规则。

Video 11 同时确认自动眩晕后的链形没有进入恢复。现已让自动眩晕和 C 共用 0.24 秒同节点收紧过程，眩晕后原链自然回直，不生成第二条 release 路径。

### 滑脱附带目标规则

- 自动满张力滑脱发生时，同一帧位于有效引导链圈内部的非接触敌人共享本次眩晕；圈内状态只用于该事件，不会转化为常驻缠绕进度。
- 自动滑脱与 C 的同链收紧过程中，使用链节点上一位置到当前位置形成的连续扫掠区域检测敌人。只有被回直链条真实扫中的目标才追加眩晕。
- C 仍只直接强制眩晕玩家端第一个接触；其他目标必须实际被收紧路径扫中，不做附近群体判定。
- 每名敌人在一次收紧事件中最多被扫掠命中一次。检测使用固定 24 节点和最多 12 敌人的既有预算，复用节点快照，不在热路径创建链条对象。
- 扫掠检测使用两级宽相位：滑脱开始以“当前链形→目标直线”的总体 AABB 建立候选缓存；每个收紧子步用当帧总体 AABB 补充移动进入的目标，再以固定 23 个链段 AABB 排除无关组合。只有通过两级 AABB 的目标才执行四边形/胶囊精确检测。
- 已命中、死亡或关闭碰撞的目标立即从候选移除；没有精确候选时只保留最多 12 次廉价总体 AABB 比较。固定链段 AABB、总体 AABB、候选数组和节点快照全部复用。

## 3. 当前单权威架构

### `PlayerState.prepareMotion`

- 更新时间、闪避、倒地和速度状态。
- 只返回本帧期望位移，不提交世界坐标。
- 旧 `update` 仅作为无运动求解器房间的兼容入口。

### `ArenaMotionResolver`

- 是铁球房内玩家最终位置的唯一运行时提交者。
- 固定顺序：输入提案 → 场地边界 → 玩家/活动敌人实体阻挡 → 直接链长上限。
- 铁球撞玩家时移动铁球；铁球撞普通敌人时移动敌人，均不反向推走玩家。
- 最终只做一次径向链长投影，不执行迭代式玩家纠正。
- `applyTaggedTetherInfluence` 是唯一例外入口，并在内部再次检查显式单位标记。
- 敌人间分离在控制器中先完成，随后才由本模块提交玩家/铁球最终位置；本帧不再有后置敌人分离覆盖已接受姿态。
- 绕体路径相对端点直线多占用的有效长度，会从下一帧玩家可继续向外移动的链长预算中扣除。普通敌人增加占用量时只阻止继续向外，不会把静止玩家被动拖回。

### `ChainSimulation`

- 维护唯一一组 24 个跨帧 PBD 折线节点。
- 节点同时供碰撞、接触顺序、局部绕角、张力、眩晕判定和渲染读取。
- 绝不写玩家、铁球或敌人的位置。
- 长度和碰撞投影会同步节点的上一帧坐标，防止纠正量在下一帧被误当成速度。
- 精确重合时使用确定性接触侧，避免链条在敌人两侧逐帧翻转。
- C 通过收紧同一组节点完成过渡；快照对象和点对象均复用。
- 圈内资格与浅接触可以同时存在；连续两次逻辑发布仍在圈内才成为释放候选。本项目按确认决定不增加自交检测，也不对自交小圈建立独立归属。
- 持续链条碰撞使用整链 AABB 和逐链段 AABB 宽相位；远端敌人不会进入节点/线段窄相位。
- `ChainWrapIntentTracker` 只维护玩家驱动的相对净绕行。它比较真实相对角位移与按玩家已接受输入重建的角位移，只累计两者同向重合部分；玩家和敌人同向等量平移时真实相对角为零，敌人单独移动时玩家贡献为零，两者都不能制造资格。
- 为区分真实绕行与固定方向直线经过，接触建立后的玩家输入方向必须相对进入方向发生至少 6° 偏转，已累计的净相对角才作为绕行证据发布。该偏转只比较进入方向与当前方向，不累计每帧转角，也不读取 PBD 绕角变化，因此不会被接触节点抖动或绕角暂时下降重置。
- 自动眩晕要求当前真实链形绕角和同向净玩家绕行都至少达到 45°；玩家反向移动会抵消绕行证据。接触发布允许固定 2 帧容错，短暂节点抖动只保留证据、不累计缺失期间的移动，超过容错后才清除。此前 8° 玩家绕行门槛会把敌人旁的小幅转向误判为完成缠绕，已按 Video 18 行为复核移除。
- `ChainReleaseQualification` 是每名当前接触敌人的统一资格快照，集中发布接触角、玩家净绕行、有效张力、各门槛布尔值和唯一阻塞原因。自动滑脱与 HUD 读取同一份结果，不再分别推断。

### `ChainRouteSnapshot`

- 是玩法与 Sprite/Graphics 渲染共同读取的唯一发布路径。
- 每逻辑帧发布一次；消费者只读。
- 点、累计长度与接触范围使用固定容量/复用缓冲区，稳定态不按帧创建链条对象。

### `ChainVisualDynamics`

- 位于权威快照之后，固定使用 16 个预分配视觉节点做有限偏差的显示采样；玩家端移动时立即同步整条视觉路径，不保留跟随惯性。
- 两端始终钉在权威路径；内部节点最大只能偏离采样目标 6 像素，并在静止后休眠。
- 只发布给 Sprite/Graphics 渲染，不导入敌人模型，也不向 `ChainSimulation`、玩家或铁球回写。
- 按本阶段范围不实现松链、接触、正向缠绕和反向解绕的专属表现；所有区间使用同一动力参数。接触范围只用于链节前后景遮挡。

### Sprite 表现层

- `ArenaSpriteRenderer` 启动时一次创建玩家、12 个敌人、铁球和 8 个桶的固定 Sprite 池。
- 场地、单位、铁球、桶和链节共用一张启动时生成的 512×512 RGBA 图集；不再依赖 SVG 导入/解码，固定约占 1 MiB RGBA 内存并减少纹理切换。
- `ArenaSpriteRenderer` 缓存节点位置、激活状态、尺寸和颜色；`SpriteChainRenderer` 在视觉快照 revision 与震屏偏移均未变化时跳过整池更新。
- 攻击扇形、瞄准、血条、眩晕、爆炸、触屏提示和 F2 调试线仍使用 Graphics，因为这些是少量动态覆盖层。

### 碰撞恢复

- 眩晕期间碰撞仍完全关闭。
- 眩晕结束后使用 0.18 秒碰撞强度恢复，玩家、铁球、敌人和链条分离量从 15% 逐步恢复到 100%，避免同位置目标瞬间弹开。
- 恢复期同时保留攻击冷却，避免敌人在仍重叠时立即攻击。

## 4. 每帧执行顺序

1. 输入生成玩家期望位移。
2. 铁球只积分自身速度和边界。
3. 敌人更新 AI；敌人之间做固定两轮实体分离。
4. `ArenaMotionResolver` 一次提交玩家位置，并处理玩家/铁球/敌人的单向碰撞权威。
5. 若上一帧满张力接触来自 `tetherInfluence` 单位，运动求解器应用该单位的实测位移并触发摔倒。
6. `ChainSimulation` 用最终端点和敌人位置做固定子步，发布一份路径快照。
7. 自动眩晕或 C 事件改变敌人状态；渲染只读取上述快照。

普通敌人永远没有从第 6 步回写第 4 步玩家位置的通道。

## 5. 性能边界

| 项目 | 上限/策略 |
| --- | --- |
| 活动锁链 | 1 条 |
| 活动敌人 | 12 |
| 同时发布接触 | 4 |
| 链节点 | 固定 24 |
| 视觉节点 | 固定 16，最大偏差 6 像素 |
| 约束迭代 | 固定 4 |
| 逻辑步长 | 60 Hz |
| 单渲染帧补步 | 最多 3 |
| 可见链节 Sprite | 最多 64，固定池 |
| 实体 Sprite | 玩家 1、敌人 12、铁球 1、桶 8，启动时固定创建 |
| 热路径分配 | 节点、contact、range、累计长度和快照对象复用 |

控制器与显示热路径还复用输入动作、移动向量、爆炸回调、绘制颜色和链节采样结果；特效与存活敌人计数改为原数组/直接循环，不再每帧 `filter()`。特殊标记单位按确认继续读取上一帧接触状态，以保留固定低成本和可接受的一帧滞后。

当前 Node 压力夹具覆盖 12 敌人运行 120 逻辑帧，并检查节点和接触上限。它只能证明算法预算受控，不能替代微信低端真机 CPU、GC、GPU 和 draw call 测量。

## 6. 已执行的严格自动测试

新测试文件：`tests/chain-rewrite.test.js`。

- `prepareMotion` 不写玩家坐标。
- 普通敌人的链条接触不改变已提交玩家位置。
- 链长裁剪不反转玩家输入方向。
- 玩家对铁球、铁球对普通敌人的单向碰撞权威。
- 眩晕敌人允许玩家穿过。
- 普通单位被特殊影响入口拒绝；只有 `tetherInfluence` 单位能平移端点并使玩家摔倒。
- 24 节点路径、真实接触累计长度、只读快照和节点对象复用。
- C 在有接触和无接触时都启动同链过渡。
- 多个接触按链节点顺序发布，且受固定上限约束。
- 静止对称接触连续 120 帧不换边。
- 局部绕角 ≥45°且张力 ≥98%时自动眩晕。
- 自动眩晕后原节点链进入收紧，弯曲偏差持续下降而不是冻结大圈。
- 单链段局部求解超长、自由链段保留松弛轮廓或玩家回走，都不能把整条链误报为满张力。
- 自动滑脱时，同一有效链圈内的非接触目标共享眩晕。
- 回直链条扫中的路径内敌人眩晕，扫掠区域外敌人不受影响，静止退化链段不产生远端误伤。
- 两级宽相位结果与直接精确扫掠逐夹具一致；远端目标在整体 AABB 层被排除，23 个链段 AABB 对象跨帧复用。
- 12 敌人预算压力夹具。
- 控制器结构测试确保旧链权威、旧二次长度约束和旧耦合碰撞不再接入运行路径。
- 敌人间分离先于最终玩家/铁球提交；后续没有同帧覆盖。
- 浅接触目标仍可在稳定两帧后成为圈内候选，离圈后立即失效。
- 绕体占用长度减少未来向外活动余量，但普通目标不能把静止玩家拉回。
- 持续碰撞宽相位能把远端 12 敌人的链段窄相位检查降为 0。
- 眩晕结束后的重叠以有限时间渐进分离，不在首帧恢复时完全弹开。
- 扫掠宽相位使用独立暴力几何参考逐夹具验证，不再用优化实现自证。
- 已拉满链条被敌人从外部碰触时，即使碰撞折角超过45°也不会自动眩晕；玩家实际绕行后，同样的45°＋满张力条件仍可触发。

当前运行架构的唯一自动验收入口是 `tests/chain-rewrite.test.js`；旧 `tests/chain-snare.test.js` 已随旧体系退役。
